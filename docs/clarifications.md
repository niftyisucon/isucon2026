### #117 再起動試験でのインスタンス再起動の回数（amago、質問 17:15 / 回答 17:16）

- 質問: 再起動試験について、FAILになった場合は再度インスタンスが再起動されますか？（マニュアルの追試手順: 最終スコアが記録された競技環境のルーターをターゲットに負荷走行を行い、結果がFAILもしくは最終スコアの75%以下の場合は負荷走行を再実行して再度判定する。2回目の再実行＝合計3回目でも同様の場合は失格）
- 回答: 再起動は1度のみ行います。

### #107 ココロザシ賞の最も近いチームの決定方法（最終人間船、質問 15:59 / 回答 16:10）

- 質問: ココロザシ賞について、最終スコアが55,634に最も近いチームが複数いた場合、どのように決定するか。
- 回答: 原則として、順位が高いチームを対象とする。1点高いチームと1点低いチームがいた場合、1点高いチームを採用する。全く同じ点数で55,634に近い場合、先にそのスコアに到達した方を採用する。

### #88 最終計測時の 192.168.10.10:8080 へのアクセス検証コマンド（全体公開・運営発、2026-10-31 15:28）

- 運営からの告知: 最終計測時、他のインスタンスから 192.168.10.10:8080 にアクセスできる場合は失格。その検証コマンドは `curl 192.168.10.10:8080 --connect-timeout 5` で、5秒後にタイムアウトすることが正。

### #84 最終計測時の 192.168.10.10:8080 へのアクセス検証コマンドの提供（くすサポISUCON部、質問 15:18 / 回答 15:24）

- 質問: 最終計測時、他のインスタンスから 192.168.10.10:8080 にアクセスできる場合は失格とされているが、運営の保証する検証コマンド等は提供されるか。
- 回答: `curl 192.168.10.10:8080 --connect-timeout 5` で実施予定。

### #55 ルータを介する通信について（全体公開・運営発、2026-10-31 13:01）

- 運営からの告知: ほかのインスタンスへの通信することを目的とした、ルータのIPアドレスを宛先とする接続（443, 8080ポートへの接続）は、マニュアルに記載されている「サーバのリージョン、通信遅延、帯域制限を変更または回避すること」に該当します。禁止事項ですので実施しないでください。

### #46 Fly High賞の「前回比のスコア上昇幅」の「前回」とは（もなまっち、質問 12:15 / 回答 12:17）

- 質問: 「前回」は、直前に行った（0点ではない）負荷走行のスコアか、それまでのベストスコアか。
- 回答: 直前に行った（0点ではない）負荷走行のスコアです。

### #41 FAILした負荷走行は各賞の基準に含まれますか（もなまっち、質問 12:05 / 回答 12:11）

- 質問: スピード10倍賞の「チームで最初に計測したベンチマークスコア」と Fly High賞の「前回比のスコア上昇幅」の「前回」に、FAIL（0点）となった負荷走行は含まれますか。
- 回答: どちらも0点は含まれません。

### #40 激流賞の「スコアボードクローズ（17:00）後のスコアの伸び」とは（もなまっち、質問 12:05 / 回答 12:10）

- 質問: 伸びは、17:00時点のスコアと最終スコアの差と比のどちらで比べるか。また「17:00時点のスコア」は、その時点で最後に行った負荷走行のスコアか、それまでのベストスコアか。
- 回答: 1. 17:00時点のスコアと最終スコアの差で計算されます。2. 「17:00時点のスコア」は、17:00よりも前にEnqueueされた0点ではない最後の負荷走行のスコアを示します。

### #39 画像URLの検証について変更は認められていますか（全体公開・運営発、2026-10-31 12:02）

- 回答: マニュアルに記載があるとおり、署名と期限の形式や検証結果を変えてはいけません。有効期限については、ベンチマーカが許容する限り変更しても構いません。

### #32 最終チェックの制限時間の記載はありますか（team yuki2006、質問 11:50 / 回答 11:55）

### #20 europe1 / america1 の nginx から asia のアプリへ proxy_pass する構成は許容されますか（boulder、質問 10:45 / 回答 10:48）

- 質問の前提: サーバ間の通信は VPC のルートどおりルーターを経由し、リージョン間の遅延・帯域制限もそのまま受ける。ユーザーの接続先（X-Country-Code による振り分け）は変更しない。
- 回答: はい。

### #6 CloudFormation で AZ の在庫不足エラーになり競技を開始できない（haigyo、質問 10:07 / 回答 10:14）

- 回答: AZ 上の在庫がなくなっているため、ポータルから生成される CloudFormation の `GetAvailabilityZoneFunction` 内の `ZoneIds = ['apne1-az2']` を `['apne1-az1']` もしくは `['apne1-az4']` に書き換えて再作成してください。

### #3 ベンチマーカー実行の自動化は許容されますか（あとで、質問 10:04 / 回答 10:05）

- 回答: はい。
