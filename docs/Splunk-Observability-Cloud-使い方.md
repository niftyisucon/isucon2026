# 📈 Splunk Observability Cloud 使い方

## これは何か

ISUCON2026 の監視用に用意した **Splunk Observability Cloud**（旧 SignalFx）です。練習と本番で、サーバーの CPU・メモリなどが飽和していないかをここで確認します。

- Realm：`au0`
- 組織名：ニフティ株式会社（申込フォームの都合で会社名になっているが、利用自体は個人の趣味としての ISUCON 用。そのまま使う方針）
- プラン：Free Edition（ISUCON スポンサー提供。15 hosts まで、利用期限の表示なし）
- 登録日：2026-10-24

## アクセス方法

- URL：[https://app.au0.signalfx.com](https://app.au0.signalfx.com)
- ログインアカウントは小松が保持している。チームメンバー（熊谷・みちと）は組織の管理者として参加している。
- エージェントは勝手にアカウントやトークンを作らない。アクセスが必要になったら人間に依頼する。

## データの流れ

1. 監視対象ホストに **splunk-otel-collector** を入れる
2. Collector が **Ingest トークン**を使ってメトリクスを送信する
3. Splunk 側のダッシュボードでホストの状態を見る

### 現在の導入状況

- 練習環境では **app-1 にのみ** Collector を導入済み（2026-10-24、チューニング終了後も残置）
- 本番用4台の導入手順は [4台にSplunk監視を導入する](splunk-setup.md) を参照。Collector導入、トークン対話入力、Goトレース有効化を人間が順に実行する。コードと手順の追加だけでは本番に反映されない

## トークンの扱い

- 使用中の Ingest トークン名：`isucon2026pre`（INGEST 専用）
- 有効期限：**2026-11-23**（大会当日 10-31 は有効期限内なので問題なし）
- 期限が切れたトークンはローテーションできない。必要なら新規作成する
- 読み取り専用トークン `isucon2026-agent` は**未作成**。エージェントが API でデータを読む必要が出たら、小松に発行を依頼する

> 🔒 トークンの値はこのページを含むどこにも書かない。値が必要な作業は人間が行う。

## 何を見るか

練習での学び：ボトルネックは **2 vCPU の飽和**で、改善が効いたのは「DB アクセス回数を減らす変更」だけだった。ベンチ中はまずここを見る：

- **CPU 使用率とロードアベレージ** — 飽和していたら、アプリ側の処理回数を減らす方向を疑う
- メモリ使用量とスワップ — メモリ不足による極端な遅化がないか
- ネットワーク — 転送量が頭打ちになっていないか
- ホストが Splunk に現れない場合 — Collector が起動しているか、Ingest トークンが正しいかを確認（人間に相談）

## エージェント向けルール

- Splunk の画面確認は人間（または発行済みトークンを持つ仕組み）に任せ、エージェントは勝手にログインを試みない
- アラートやダッシュボード、トークンを勝手に作成・変更しない
- ベンチ結果を #agent-log に投稿するとき、Splunk で見た飽和状況があれば一言添えると人間の判断が速くなる
